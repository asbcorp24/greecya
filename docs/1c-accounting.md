# Обмен с 1С:Бухгалтерией

CRM «Греция» поддерживает исходящий обмен с 1С через опубликованный HTTP-сервис 1С.

## Архитектура

CRM формирует пакет за выбранный период и либо:

1. отдаёт его бухгалтеру как JSON/XML-файл;
2. отправляет HTTP POST на URL, указанный в `/admin/accounting`.

Это транспортный адаптер «Греция → 1С». XML `GreecyaAccountingExchange` является собственным форматом проекта, а параметр `format_version` хранит целевую версию EnterpriseData для последующего маппинга на стороне 1С. Не следует принимать этот XML за штатную XDTO-схему EnterpriseData.

## Состав пакета

- `counterparties` — клиенты/контрагенты;
- `nomenclature` — товары, билеты, абонементы и сертификаты;
- `sales` — оплаченные продажи с табличными частями;
- `returns` — возвращённые заказы;
- `payments` — оплаты и возвраты платежей;
- `cash_operations` — кассовые операции по наличным, карте, СБП и другим методам;
- `meta` — период, источник, организация, версия и количество записей.

Идентификаторы имеют стабильный вид `customer:123`, `product:10`, `order:55`, `payment:77`, чтобы расширение 1С могло хранить соответствия и обеспечивать идемпотентный импорт.

## HTTP

Метод: `POST`.

Content-Type:
- `application/json` для `json_http`;
- `application/xml` для `xml_http`.

Служебные заголовки:

```text
X-Greecya-Exchange: accounting
X-Greecya-Format-Version: 1.23
X-Greecya-Signature: <HMAC-SHA256 тела, если задан token>
```

Аутентификация:
- при логине используется HTTP Basic Auth;
- если логин не задан, но задан token — Bearer Token;
- HMAC-заголовок формируется тем же token и позволяет дополнительно проверять неизменность тела.

## Минимальный обработчик в 1С

На стороне 1С рекомендуется опубликовать HTTP-сервис, например:

```text
/hs/greecya/accounting
```

Обработчик должен:

1. проверить авторизацию и, при использовании HMAC, подпись тела;
2. определить JSON/XML по `Content-Type`;
3. разобрать пакет;
4. найти или создать соответствия внешних идентификаторов;
5. записать контрагентов и номенклатуру;
6. провести продажи/возвраты/оплаты/кассовые операции согласно учётной политике конкретной базы 1С;
7. вернуть HTTP 2xx только после успешной фиксации транзакции;
8. вернуть JSON с результатом и диагностикой при ошибке.

Пример успешного ответа:

```json
{
  "success": true,
  "exchange_id": "1c-20260822-0001",
  "accepted": {
    "sales": 12,
    "returns": 1,
    "payments": 13
  }
}
```

## Важное ограничение

Конкретные объекты 1С (документы реализации, поступления на расчётный счёт, операции по платёжным картам, чеки ККМ и т. п.) зависят от версии и настроек конкретной `1С:Бухгалтерии`. Поэтому маппинг выполняется расширением/HTTP-сервисом 1С, а Laravel не привязан к внутренним метаданным одной конфигурации.
